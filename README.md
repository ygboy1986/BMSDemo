# BMS Modbus Bluetooth（Objective-C）

原生 iOS 应用，包含产品信息、数据监控、设备功能、固件升级、历史数据五个 Tab。应用只连接真实蓝牙设备，不再展示本地演示型号、容量、参数、识别码或示例地址。模拟 Transport 仅供离线协议测试使用，不由 App 创建。

## 连接与读取

1. 使用 Xcode 打开 `BMSModbusDemo.xcodeproj`，选择 iPhone 真机运行并允许蓝牙权限。模拟器可检查空状态与布局，不能验证真实 BLE 收发。
2. 产品信息右上角点击“连接”，进入“设备与日志”页并扫描附近的 YT/QM 设备。
3. 点击电池设备，待服务发现、通知启用完成后，自动依次读取 D0～D49 设备信息和 D300～D341 电池参数。返回“产品信息”查看真实响应；也可点击“刷新产品信息”重新读取。
4. 点击电池包或右下角按钮打开电芯参数页。“读取设备参数”会重新发送请求，不读取本地预设或缓存。
5. 在参数页点击“电池类型”，弹出“三元锂／磷酸铁锂／测试”滚轮；取消不更改选择，确认仅选择待应用的类型，页面继续保留设备当前读取值，并标明“尚未写入”，不会清空所有参数或用预设冒充读数。选择后点击底部“修改”，将三元锂（0）或磷酸铁锂（1）写入 D336，单项回读校验，再读取 D300～D341 全部参数。只有最终回读类型一致才报告成功，页面展示设备实际返回的阈值；不假定设备会随类型自动重置保护参数，也不写入本地阈值预设。
6. “测试”可在弹层选中，但当前协议没有定义其写入编码，点击修改会提示缺少协议，不发送猜测值。需要原 APP 选择“测试”并点击“修改”时的完整发送/返回报文才能接入。
7. 查看另一块电池：通过首页“连接”进入数据监控，点击左上角“设备”，先断开当前设备，再扫描连接另一台。

## 产品信息与参数来源

| 字段 | 来源 |
| --- | --- |
| 蓝牙设备名 | 所选设备的蓝牙扫描名称 |
| 登入时间、使用时间 | 当前蓝牙连接的本机时间、持续时长 |
| 软件版本、硬件版本、识别码 | D0～D49 设备信息区 |
| 电池类型 | D336：0 三元锂，1 磷酸铁锂；其他值显示未知及原始值 |
| 标定容量 | D338，按协议换算为 mAh |
| 电压保护/恢复、温度、均衡开启参数 | D300、D302、D303、D305、D310、D311、D323～D330 |
| 产品型号、设备地址、坐标 | 当前协议未提供，显示缺省说明，不用截图样例填充 |

参考界面中的部分电流/延时只在当前协议里定义了档位，尚无明确 A/ms 换算；这些字段和未定义的均衡关闭压差显示“—”。设备功能 Tab 可以查看全部 42 项协议原始/工程参数，包括档位。超出协议范围的返回值会标记异常。

保护参数数值仍只读；“修改”仅应用明确选择的电芯类型，不向真实电池发送演示阈值预设。切换结果不明或回读失败时清空旧参数并提示重新读取，不会伪造成功。连接断开或更换时清除产品信息和监控数据，取消未完成请求；旧设备的回调和分包不会作为新设备数据显示。读取失败显示错误，不以样例值兜底；信息区失败仍尝试读取独立的参数区。

## 其余 Tab

- 数据监控：按参考视频显示实时状态、电压信息、探针温度、5 路 MOS 状态、循环次数及 14 项报警；“查看单节电压”进入 32 路列表，“查看探针温度”展开/收起 6 路温度。支持下拉刷新、手动读取和每 2 秒自动刷新，左上角“设备”管理蓝牙，右上角“日志”分享完整收发/解析记录。
  - 进入监控页自动首次读取，先读取 D335 的实际配置串数，再读取 D96～D181 完整实时快照；忙碌跳过，不重叠请求。轮询仅在监控首页/单节详情且 App 前台时发起。
  - 总电压、电流、SOC、SOH、MOS 和温度按已有协议换算；功率由电压×电流计算。最高/最低电压、串号和压差只计算设备配置的 1～32 路；缺失串数、无效电芯值不会用零或猜测值补齐。
  - 探针最高/最低取全部 6 路，保留 0℃。当前没有有效探针数量定义，所以可能与客户 APP 排除未安装探针后的统计不同。
  - 运行模式、充放电状态、剩余使用时间、单节均衡的编码尚未确认，展示待确认/缺省值，D159～D162 原始状态字与完整 86 寄存器解析保留到日志，不根据截图写死“纯电/放电/1分/未均衡”。
  - 失败保留上次成功时间和读数，并明确标记未更新；断线/换设备清空主页面及详情。无效电压/电流/SOC/温度显示“—”，未知 MOS 值显示原值，报警无效值不显示“正常”。
- 设备功能：独立的“设备概览／常规参数”页面，点击“全部刷新”或下拉刷新，依次读取实时状态、设备信息和 42 项参数，不依赖先打开监控页。
  - 概览展示 5 路 MOS、温度、报警、软件／硬件版本、识别码、设备时间及原始自检值。
  - 参数按电压、均衡、电流、温度、校准和电池配置分组，支持名称及寄存器地址搜索；点击可查看原始值、换算、范围和读取时间。异常值保留并标红，未知类型不推断。
  - 各分组保留独立更新时间；部分读取失败仍尝试其他分组，并明确标注旧值未更新。忙碌时不重叠发送；断线清空数据和已打开的详情，旧回调不能回填。
  - 参数只读；MOS 开关控制仍等待设备写入协议确认。
- 固件升级：独立入口，完整 OTA 流程尚未实现。
- 历史数据：读取记录总数及指定索引记录。

## 蓝牙与协议

服务 UUID 为 `00010203-0405-0607-0809-0A0B0C0DFFE0`，写特征尾码 `FFE2`，通知特征尾码 `FFE1`。扫描只显示名称以 `YT` 或 `QM` 开头的设备，持续 12 秒，最多显示 50 台。

UUID 匹配失败时会枚举 GATT 服务，并尝试选择同一服务中具备写入和通知能力的透传特征。日志显示最终 Service/Characteristic UUID，量产建议将确认后的 UUID 固定回配置文件。通知启用后才允许发送请求；分片写入遵循 CoreBluetooth 流控。

- 实时读取请求：`01 04 00 60 00 56 70 2A`，起始 0x0060，共 86 个寄存器。
- 0x04 响应长度为两字节大端；实时头 `01 04 00 AC`，数据 172 字节，含 CRC 共 178 字节。支持通知分包，完整帧 CRC 通过后才解析。
- MODBUS CRC 按低字节、高字节发送；16/32 位数据按高字节在前。
- 请求超时 5 秒；超时后释放忙碌状态，不自动重试。
- 故障状态采用 Ver1.4 连续主表 D163/0x00A3；附录的 D152 与主表冲突，需硬件方确认。
- D80/0x0050 未明确定义 MOS 开/关的写值，因此 UI 未启用实机 MOS 控制。

## 代码入口

- `UI/ViewController`：五个 Tab、共享真实蓝牙客户端、设备连接/日志与功能/历史页面。
- `UI/BMSMonitorViewController`：监控卡片、32 路详情、温度展开、前台刷新、请求互斥和读数失效处理。
- `UI/BMSFunctionsViewController`：设备概览、参数分组／搜索／详情、顺序刷新与分组失败状态。
- `UI/BMSProductViewController`：真实产品信息、自动读取及电芯参数显示。
- `UI/BMSBatteryProfile`：参考界面字段与寄存器映射，不含本地产品预设。
- `Client/BMSClient`：读取/写入协议 API、参数换算、写后回读、取消未完成请求。
- `Client/BMSRealtimeData`：实时寄存器解析。
- `Transport/BMSBLETransport`：CoreBluetooth 扫描与收发。
- `Transport/BMSMockTransport`：仅供离线协议测试，不作为实际数据来源。

类型切换通过 `changeBatteryType:completion:` 调用 `writeCommonParameterAt:engineeringValue:completion:`，保留范围校验、写后回读以及完整参数复核。固件命令接口也仍未构成完整 OTA 流程。

## 日志和验证

日志保存到 App Documents 的 `BMSLogs`，每次启动创建一个文件，仅保留最近 10 份；界面保留约 3 万字符。数据监控右上角“日志”中可分享日志，也可在“文件”App 中导出。

每次常规参数响应通过 CRC 校验后，日志自动追加“参数解析开始／结束”块：

- 电芯类型单独记录 D336/0x0150、完整响应字节偏移 76～77（从 0 计数）、高低字节、16 位十六进制/十进制值与当前 App 类型映射。
- 42 项参数逐项记录寄存器地址、字节位置、原始字节/数值、倍率、偏移、工程值、单位和当前协议范围检查。
- `0=三元锂、1=磷酸铁锂`，其他返回值明确记为未知，不推断为“测试”；档位缺少 A/ms 换算时明确说明。
- 日志只解释真实响应，不使用选择器的待应用类型；异常分包或 CRC 错误不会生成成功解码记录。

升级运行后，在产品信息点“刷新产品信息”或在电芯参数页点“读取”，再到数据监控右上角“日志”点击“分享日志”，即可将原始收发与解码结果一起交给硬件工程师。

/tmp/bms-profile-tests
clang -fobjc-arc -fmodules -fmodules-cache-path=/tmp/bms-module-cache -framework Foundation Tests/BMSProtocolSmoke.m BMSModbusDemo/Protocol/BMSModbusCodec.m BMSModbusDemo/Transport/BMSMockTransport.m BMSModbusDemo/Client/BMSClient.m BMSModbusDemo/Client/BMSRealtimeData.m -o /tmp/bms-protocol-tests

离线测试覆盖用户 16:33:24 设备信息抓包（请求 `01 04 00 00 00 32 71 DF`、响应 CRC `38 8B`）、字段映射、CRC/分包、不同设备响应、类型写入/单项回读/完整回读、不一致或未连接/未知类型拒绝、取消请求及清理旧分包；这些测试不替代真机 BLE 验证。

## 两个 APP 数值差异核对

2026-09-26 客户日志截图与本 App 日志的 90 字节参数响应完全一致（CRC `09 98`）。电压和温度的原始字、换算结果、视频页面差异及未确认问题记录在 [参数对比记录](docs/parameter-comparison-20260926.md)。客户页面是否使用类型预设或另一套显示映射，需要原 APP 实际“读取／修改”时的界面与收发记录才能进一步确认；当前不为了匹配画面而改写真实寄存器的数值。


监控回归：`Tests/BMSProtocolSmoke.m` 包含视频电芯值的离线计算用例（最高/最低/压差/串号）、0值保留、无效值、报警和原始日志偏移验证。`Tests/BMSMonitorUISmoke.m` 是独立 Simulator 测试宿主，未加入正式 App target，覆盖真实协议形状的分包注入、详情刷新、忙碌跳过、探针展开、跨 Tab 暂停、断线清空和日志入口。离线测试不能代替真机 BLE 联调。

设备功能回归：`Tests/BMSFunctionsUISmoke.m` 使用独立 Simulator 宿主注入协议响应，覆盖三段顺序读取、重复刷新互斥、未知 MOS、全部 42 项参数、地址搜索／无结果状态、参数详情、部分失败保留读数、断线清空与跨 Tab 连接入口。界面截图保存在 `docs/screenshots/functions-*.png`，其中数值仅为测试输入。
